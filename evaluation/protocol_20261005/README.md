# 防过拟合评测协议（2026-10-05）

本轮仅在本地审计、准备索引，没有新增模型请求。此前反复使用的 SVEN 和 Devign 小样本结果只算开发证据，不算独立测试成绩；对同一批 30 条复测两遍，独立样本量仍然是 30。

## 本地审计结果

Devign 原始 27,318 条。历史准备批次和训练缓存共涉及 14,143 条索引；相同规范化源码或相同项目/提交连接成组后，连同冲突标签组共排除 22,061 条，保留 5,257 条候选数据。

分组后按固定种子 20261005 的哈希分配，比例约 60/20/20。没有为了改善指标重抽样或强行平衡类别。索引清单不包含源码或标签。`verification.json` 已验证跨分区索引、规范化源码、提交和连接组无交叉，且与记录的历史索引没有交叉；同时保存清单 SHA-256。

## 仍需完成的隔离检查

- 本地记录未覆盖的历史使用无法排除，不能把“未发现记录”写成“从未使用”。
- 当前识别忽略注释/排版的相同源码；变量改名和近似克隆尚未识别。完成这一检查之前，不释放 locked_test。
- 这是补充分组验证协议，不是官方 Devign 折分；不能用它冒充论文官方 benchmark。
- checkpoint 的内部 holdout 是模型选择集，不是整体系统的最终独立测试集。

## 后续执行规则

1. 仅在 development 调整图压缩、提示、规则、阈值和 GAT。先补齐近似克隆隔离，再固定清单；不得通过查看测试得分选择近似克隆阈值。
2. validation 只比较预先指定的标准配置和类型补全候选；完整保留两组结果。禁止测试许多变体后只报告最高分。此前已试过的多个变体必须在开发记录中披露。
3. 主要指标预设为函数级 binary F1，同时报告 Accuracy、Precision、Recall、自然类别比例、平均/总实际 token 和失败数。按源码/提交连接组计算配对置信区间，重复调用不能增加独立样本数。报告每次复测，不能挑最好的一次。
4. 在 validation 上确认候选与 token 权衡后，冻结代码、模型/服务身份、配置、阈值、清单哈希和统计方案，再一次性评测 locked_test。不得用 locked_test 的错误案例继续调参然后仍称其为独立测试。
5. 任何测试后的进一步改动都回到开发流程，并需要新的独立测试数据。若失败或区间包含零，如实报告“未证实稳定提升”，不追着该测试集改规则。
6. 大规模外部调用必须先获得相应数据范围与 API 用量授权。此前 30 条 Devign、120 次调用的授权不自动扩展到这里的全部数据。

另外修复了预测缓存指纹：现在同时包含实际配置的模型名和服务地址（仅进入哈希，不输出密钥），防止换模型/服务后误复用旧预测。33 项相关离线测试通过。
