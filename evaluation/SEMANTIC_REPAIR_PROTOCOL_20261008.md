# Semantic repairs and assignment evidence: frozen confirmation protocol

Registered before sample labels/predictions or real calls, 2026-10-08.
Human approved 60 new public Devign development groups, control/candidate twice
(240 scheduled results), sending SRC, graph paths and reasoning context to
https://api.deepseek.com/v1, configured deepseek-chat. No validation/locked-test
external payload is authorized in this batch. SDK retries disabled; observed
wrapper maximum three attempts/call, 90s timeout, at most two reasoning steps.

## Common repairs, not candidate benefits

Both profiles use identical corrected full-denominator metrics, restricted
straight-line source-verifier policy, independent bidirectional capacity,
cycle exclusion, hop limit, monotone threshold search, final-vs-main records,
uncertainty handling and fingerprint-respecting cache failures. These are a
new version; historical v20/v22 scores are not its benchmark results.

Legacy lexical source signals remain diagnostic only. Restricted release/use
patterns assume ordinary C/library contracts; this is not a path/alias solver.
Unsupported branches/calls cannot force a positive verdict. No GAT, graph net,
ACTION-first, grouped evidence or observed-state activation.

## Single core candidate

SOURCE_SLICE_ASSIGNMENT_FIX alone: retain ordinary assignment/increment and
leading-pointer-write source lines instead of mistaking them for redundant text
or comments, within the existing SRC character budget. Control=0, candidate=1.
No changed system prompt, model, graph ranking, token ceiling or verifier.
This is operation-centered evidence preservation, not complete slicing or
an assertion of exact provider-token equivalence. Candidate remains default OFF.

## Inputs and execution

Use clone-v2 development only, seed20261011, one fixed representative per group,
exclude every recorded local exposure group; choose before accessing labels.
Keep all 60 scheduled samples including CPG/API failures, no replacement.
Freeze dataset/selection/preparation/code/graph hashes and effective per-profile
settings in manifests and a saved prediction-code snapshot before real calls.
Use fresh calls for both profiles/repeats; don't re-use historical answers.
First repeat primary, second sensitivity; repeated calls are not new groups.
Keep raw responses, request payloads, actual returned model, finish reasons,
known tokens from failed pipelines and unknown-usage invocation counts.

## Predeclared interpretation and downstream gate

Report full-denominator Accuracy, conservative positive F1, confusion matrix,
coverage/failures/uncertainty, MCC/balanced accuracy, constant-positive and
constant-negative references, returned tokens, truncation, repeat disagreement,
paired group bootstrap 95% intervals (2000 draws, seed20261007).

For moving to a separately authorized validation stage require:
(1) candidate F1 and Accuracy >.60 in both repeats;
(2) candidate beats constant-positive on Accuracy and has positive MCC;
(3) candidate-control F1/Accuracy point deltas nonnegative in both repeats;
(4) primary interval lower bound >0 on at least one metric and >=0 on the other;
(5) no aggregate returned-token increase in either repeat;
(6) actual candidate input differences documented, no provenance/contract errors.
These are strict development gates, not claims of definitive significance or
future provider stability. No automatic default promotion or locked-test launch.
Failure means record the negative outcome; no favorable rerun, threshold tuning
on these now-exposed samples, or retrospective subgroup selection.

Regardless of scores, audit actual changed inputs versus unchanged-input pairs:
unchanged-prompt variability cannot be attributed to the candidate. Final test
and a submission venue/manuscript approval are separate steps; not authorized
external manuscript submission by this protocol.
