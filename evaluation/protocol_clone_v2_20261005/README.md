原始协议保留在 `evaluation/protocol_20261005/`，没有覆盖或重新分配任何样本。
本版仅删除有隔离风险的连接组，并重新记录连接组标识。

固定代码规则，不使用标签/预测调整阈值：

- C/C++ 关键字和字面量保留，其他标识符按首次出现一致归一化；完全相同的
  token 序列合并，共发现 1238 对。API 名称也归一化，可能保守地合并独立函数。
- 至少 60 token 的函数，五词片段集合 Jaccard >= 0.90 合并，共发现 497 对。
  前缀过滤加完整相似度核对，不使用随机候选抽样或候选数量上限。
- 与任一原先排除的组连接，删除整个相关保留组；跨分区克隆也整组隔离。
  共删除 304 条，其中 266 条触及原先排除组，38 条跨分区；没有移动样本来
  改善分区结果或平衡标签。

`verification.json` 已核对原始数据 SHA-256、清单源码哈希和项目/提交身份，
历史索引交叉及跨分区索引/源码/提交/连接组交叉均为零。规则代码和测试在
`evaluation/quarantine_near_clones.py`、`evaluation/test_near_clones.py`。

限制：不是全部语义克隆检查；短函数只检查归一化完全重复；五词集合忽略
顺序/重复次数，64 位片段哈希存在理论碰撞风险，倾向保守误合并。未记录的
历史使用仍不能排除。这里是补充隔离协议，不是官方 Devign 折分。

## 预先规定的后续比较

1. development 才用于改动、错误分析和选择候选。新的开发批次固定随机种子、
   固定源码/提交组，不按预测难易或标签挑选。保留失败实验，不选最好的一次。
2. validation 比较冻结的标准 HGL 和单一选定候选；纯 LLM 为额外基线。
   三者使用相同样本、配置的模型/服务、标签定义和失败处理。纯 LLM 接收完整
   函数，不能悄悄截断后仍称完整源码基线；超限样本/调用失败单列。
3. 主目标是 binary F1 和 Accuracy 同时 >0.60；同时报告 Precision、Recall、
   混淆矩阵、实际 token、失败率及源码/提交连接组配对区间。过线仅是目标，
   不能强迫实验结果达到；不能只展示有利子组或删除难例。
4. 固定模型、提示、代码、预算、数据清单、主要统计方案后，再一次性评测
   locked_test。验证集上的候选筛选要披露；不能声称验证集是最终独立测试。
5. 与其他论文比较须核实同一数据/划分/评价定义以及模型差异。不能直接用
   此补充协议的分数与另一篇论文的官方划分分数作优劣结论。
6. 当前类型覆盖仍为 F1 开发候选。早期源码窗口实验因位置属性丢失而无效；
   修复后真实窗口实验 F1/Acc 均下降，已拒绝。不得把早期指标当作收益。
   分组重训 GAT 也未通过独立校准，未启用。版本台账：
   `evaluation/VERSION_LEDGER.md`。

本轮仅本地隔离/测试：零模型调用，未读取锁定测试集预测。
